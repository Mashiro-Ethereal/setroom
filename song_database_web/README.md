# 乐队曲库 · 云端版

这个文件夹是一份独立的 Cloudflare 网页版。原来的 `../song_database/` 程序和数据库完整保留作本地版本。迁入后以云端为主，两份数据不会自动同步。

## 仓库与配置

这是 Cloudflare Workers + D1 的独立网页版，可部署到自己的 Cloudflare 账号。日常操作见 [使用指南](使用指南.md)。

真实数据库、备份、登录 Key、Wrangler 授权信息以及实际部署配置均不在仓库中。首次克隆后，将 `wrangler.example.jsonc` 复制为 `wrangler.jsonc`，再按下文运行。已有本机部署配置无需覆盖。

## 使用方式

打开网站，输入乐队标识和本乐队 Key；KRB 默认标识为 `krb`。网站管理员通过 `/login?admin=1` 登录管理后台。登录页的“申请创建乐队”会提交待审核申请，批准后才能访问。

- 乐队成员均可管理本乐队的四个模块、导出 Excel、备份和恢复；网站管理员可进入所有乐队。
- 登录有效期为 12 小时；点击“退出登录”即可退出。关闭网页不会关闭云端服务，电脑也不需要开机。

全新数据库初始化时包含少量虚构的示例曲目和演出，可在页面中删除。

### 语言分类

所有模块（含历史记录、历史歌单）只提供“仅日语”和“全语种”两个选项。原先仅有日语、或未注明的归为“仅日语”；含中文、英语或英文的归为“全语种”。已准备好翻译演唱版本的歌曲可手动改为“全语种”。筛选中的“全部分类”表示不筛选。Excel 使用相同分类。

### 曲库与演出

曲库是歌曲资料的统一来源；不同版本分开管理。未来演出引用曲库当前信息。确认演出完成后，歌单中的名称、版本和语言会保留当时的记录；以后修改曲库不会改写历史歌单。历史记录可单独更正本场资料。

先在曲库添加歌曲，再为演出选歌。可以调整歌单顺序、添加备注。被演出引用的歌曲不能直接删除；不再演出的歌曲可改为“取消”。演出结束后确认日期及实际歌单，再归档。

歌名、版本支持双向排序，演出经历可按场数或最近日期排序；语言、状态保留筛选。歌曲排序沿用本地版的中文浏览器比较规则，日文与中文不转写拼音或罗马音。

曲库可导出全部或筛选结果，演出详情可导出本场歌单。Excel 在浏览器生成，请查看浏览器下载列表；成员也能导出。

### 愿望单

侧栏“愿望单”记录想排的歌，独立于曲库。包含曲目名称、版本、语言、发起人和“我也想排”；没有状态或演出经历。

KRB 的发起人从固定成员中单选，“我也想排”可多选或留空：🎸ko、🎸mu、🎤🐱、🎹伟、🥁钱。支持名单会去重。全体成员都可以新增、编辑、删除、筛选排序和导出 Excel。页面与导出文件都会显示成员的 emoji。

朋友乐队的发起人与“我也想排”为纯文本，支持 emoji，不需要成员名单。填写方式随乐队配置决定，新乐队默认文本模式。

愿望单支持按曲目名称、版本双向排序，按语言筛选和文字搜索，可导出全部或筛选结果。管理员可点击最右侧“加入曲库”，确认后将该愿望的名称、版本和语言移入曲库，状态为“大饼”，同时从愿望单移除。新增曲库记录与移除愿望在同一事务中完成；重复点击或过期页面会提示刷新。发起人和支持名单属于愿望单，移入曲库后不再展示。

### 备份与恢复

管理员点击“备份与恢复”下载 JSON 文件。Excel 用于分享，不包含完整恢复信息。恢复 JSON 只替换当前乐队的数据；应用保留最近一次恢复前的备份，可下载后再恢复。单次上传上限为 2 MB。新版 JSON 备份（version 4）包含乐队归属和愿望单填写方式，只能恢复到对应乐队。KRB 兼容 version 1/2/3；version 1/2 自动转换语言，version 1 保留现有愿望单。恢复不修改乐队设置或 Key。

本地版 SQLite 备份不能直接上传到这里。迁移时需先转换为兼容的 JSON，并校验字段、歌曲关联、历史快照和歌单顺序。恢复请使用对应乐队导出的 JSON 备份。

多窗口同时修改同一条记录会提示冲突。登录过期或网络故障时，未保存表单会保留；按页面提示重新登录或恢复网络后重试。更换数据库备份后，旧页面需要刷新。

## 本机开发

需要 Node.js 22.13 或更新版本（推荐 LTS）。所有命令在本目录运行。

```sh
cp wrangler.example.jsonc wrangler.jsonc # 仅首次克隆时执行，不要覆盖已有配置
npm ci
node scripts/setup-local.mjs
npm run db:local
npm run dev -- --port 8787 --ip 127.0.0.1
```

首次生成的本地乐队 Key 保存在 `.access.txt`，网站管理员 Key 保存在 `.platform-access.txt`；生成脚本不会覆盖已有 `.dev.vars`。打开 `http://127.0.0.1:8787`。停止开发服务时，在对应终端按 Control+C 即可。

本机 D1 数据保存在 `.wrangler/state/`；远端 D1 是另一份数据库。两者都不会读取或修改旧版目录。

如需把 Wrangler 的配置、日志也保存在新目录，先执行：

```sh
export XDG_CONFIG_HOME="$PWD/.wrangler/config"
export WRANGLER_LOG_PATH="$PWD/.wrangler/logs"
export WRANGLER_SEND_METRICS=false
```

验证：

```sh
npm test
npm run check
```

测试覆盖申请审核、跨乐队数据和引用隔离、文本愿望单、Key 重置、停用与重新启用，以及历史快照、重复演出计数、并发冲突、事务回滚、恢复验证、共享管理员权限、登录、排序和 Excel 格式；`check` 执行语法检查及 Workers 打包预演，不上传。

## 首次部署 Cloudflare

架构：一个 Worker 同时提供静态页面和接口，D1 保存结构化数据。不需要 GitHub Pages、自备域名或常驻的本机服务。使用现有免费计划，不主动升级付费服务。

1. 在本目录安装依赖并执行上述 Wrangler 环境设置。
2. `npx wrangler login --scopes account:read user:read workers:write workers_scripts:write d1:write`，在官方授权页登录并授权。授权给 Wrangler 的是账号级 Workers/D1 管理权限，不是仅限这一份应用。
3. `npx wrangler d1 list` 检查已有数据库；没有本项目数据库时执行 `npx wrangler d1 create setroom-db`。
4. 在 `wrangler.jsonc` 中设置自己的 Worker 名称和数据库名称，并将返回的数据库 ID 填入 `database_id`。如有多个 Cloudflare 账号，同时填写所选账号的 `account_id`。
5. `npm run db:remote`，应用尚未执行的结构迁移。全新数据库会初始化默认 KRB 乐队及虚构示例数据；已有数据库只应用尚未执行的迁移，不会重新写入示例。
6. `npm run deploy`，部署配置中命名的 Worker。
7. 配置 Secrets：`ADMIN_PASSWORD` 为 KRB 初始乐队 Key；`PLATFORM_PASSWORD` 为独立的网站管理员 Key；`AUTH_SECRET` 为稳定的随机会话 / 密码保护密钥（建议 32 字节随机值）。可分别使用 `npx wrangler secret put 名称`，或从私有文件 bulk 导入。
8. 打开网址验证共用口令登录、保存和 Excel 导出。

乐队新 Key 使用带随机盐的 PBKDF2-SHA256（100,000 次）校验值，另用 `AUTH_SECRET` 作服务端密码保护密钥。`AUTH_SECRET` 必须私密备份，不能当作管理员 Key 轮换，否则已有乐队密码无法校验。单独轮换 `PLATFORM_PASSWORD` 不影响乐队密码。管理员和乐队 Key 只要求填写，不设置长度或字符组合要求；申请、创建、重置与登录遵循相同规则。

KRB 初次迁移仍使用原有 `ADMIN_PASSWORD`，因此成员无需换 Key；通过后台重置后改用数据库校验值。旧的 `VIEWER_PASSWORD` 已不再使用。会话绑定乐队和凭证版本；重置 Key 或停用乐队使旧会话失效。

申请进度使用随机私密链接，数据库只存令牌摘要；公开入口不提供申请列表。申请限制为同一来源每小时 3 次，登录每 15 分钟 30 次，进度查询每 15 分钟 60 次。统计过期后自动清理。所有提交要求同源请求。

所有业务表使用乐队标识作用域；歌单使用复合外键禁止跨乐队引用。每个乐队有独立修改版本与恢复前备份。管理员身份与普通乐队身份分离，跨乐队管理接口逐次校验身份。
后续更新只需检查后运行 `npm run deploy`；若增加数据库迁移，先执行 `npm run db:remote`。上传范围只有 `src/` 编译结果和 `static/` 静态资源，不包含旧版本地数据库。

`.dev.vars`、`.access.txt`、`.platform-access.txt`、`.wrangler/` 包含私密配置或授权信息，已加入忽略列表；也不要把整个目录原样公开分享。

官方文档：[Workers](https://developers.cloudflare.com/workers/) · [D1](https://developers.cloudflare.com/d1/) · [Wrangler 登录](https://developers.cloudflare.com/workers/wrangler/commands/general/#login)

`src/legacy-redirect.js` 是原部署从测试站迁移到正式站时使用的跳转程序，保留作历史兼容；默认部署不使用它，新部署无需配置该 Worker。

管理员可永久删除一个乐队及其全部业务数据和站内恢复前备份，需要输入完整乐队名称确认。删除通过 D1 原子批次完成，每条语句都校验乐队与设置版本；其他乐队不受影响。
